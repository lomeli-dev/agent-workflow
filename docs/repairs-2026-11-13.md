## OpenCode: el fallo ya no depende sólo de una instrucción

El plugin V2 registra un hook nativo de shell antes de la ejecución. Con el workflow activo, rechaza validaciones reconocidas combinadas con pipes, separadores o condicionales. El agente debe ejecutarlas directamente, usando el campo cwd para el directorio. No se reescribe silenciosamente el comando y no se ejecuta una parte antes de rechazarlo.

Prueba real con OpenCode 2.2.7 y un test que termina deliberadamente con código 7:

| Caso | Observado |
| --- | --- |
| Workflow activo, `npm test; echo MASKED > masked.txt` | Error `AW_VALIDATION_COMPOUND`; no se creó masked.txt |
| Reintento permitido, `npm test` directo | El tool devolvió exit 7 y el agente lo informó |
| Workflow desactivado, mismo compuesto | Se ejecutó y creó masked.txt; el plugin respetó el opt-out |

El test crea su propio marcador al ejecutarse. La evidencia de rechazo viene del hook nativo y del marcador que el comando posterior no pudo crear; no se aceptó únicamente la afirmación del agente.

El guard cubre formas reconocibles de npm/pnpm/yarn/bun, node --test, pytest/unittest y otros runners conocidos. No es un parser universal de shell ni un sandbox: scripts arbitrarios, sustituciones y formas no reconocidas siguen requiriendo validación independiente. El gate se consulta en cada llamada. Si el cliente no ofrece la API de hook, queda indicada la ausencia de capacidad en el estado del plugin; no se promete protección activa.

La API utilizada está documentada en [OpenCode Server plugins](https://opencode.ai/docs/build/plugins/server/).

## CodeGraph: fallback real de símbolos para módulos JS/TS

La versión publicada 0.21.0 y el registro de extensiones de su parser siguen omitiendo `.mjs`. No se modificó su binario ni se renombraron archivos del usuario.

La integración ahora:

1. Añade una advertencia de cobertura cuando el grafo devuelve una lista vacía.
2. Expone `agent_workflow_symbols` como herramienta MCP separada.
3. Permite también `agent-workflow symbols --project RUTA --file src/modulo.mjs --name nombre`.
4. Usa el parser TypeScript para obtener declaraciones nombradas del archivo original, sin ejecutar su código.
5. Identifica explícitamente `source: typescript-parser` y `graphRelationships: false`.

La prueba directa y la prueba con un agente OpenCode encontraron `durationMs` en `sample.mjs`, línea 1, con la ruta original. El archivo quedó intacto y la conexión MCP temporal fue retirada. No se llamó grep y se presentó como MCP.

Este fallback no construye relaciones de llamadas ni arregla el grafo interno del proveedor. Acepta archivos JS/TS explícitos de hasta 1 MiB, limita resultados y rechaza escapes del proyecto, sintaxis inválida y opt-out. `setup` de CodeGraph resuelve el requisito TypeScript; no instala nada durante una llamada MCP.

La limitación del proveedor se corroboró en [su parser TypeScript](https://github.com/codegraph-ai/CodeGraph/blob/main/crates/codegraph-typescript/src/parser_impl.rs).

## Compactación y retomado reales

Se creó una sesión sintética en OpenCode, con un marcador importante únicamente en la conversación y un archivo CHECKPOINT.md con el siguiente paso, sin ese marcador. Para que el ensayo comprobara la recuperación desde el resumen, sólo el fixture usó `compaction.keep.tokens=0`; no se cambió la configuración global.

Después de cerrar el primer proceso CLI:

- Se solicitó compactación mediante la API nativa, con un identificador de solicitud propio.
- Se abrió de nuevo la misma sesión.
- El registro nativo confirmó una compactación completada, no sólo una petición aceptada.
- El agente recuperó el marcador sin llamar herramientas ni leer archivos.
- El checkpoint se conservó byte por byte.

Es una prueba real y acotada de compactación y continuidad de sesión, no una prueba de carga de varios días ni de recuperación ante cualquier fallo. Los hooks de otros clientes siguen teniendo sus propias capacidades y aprobaciones. [Documentación de compactación](https://opencode.ai/docs/compaction/).
